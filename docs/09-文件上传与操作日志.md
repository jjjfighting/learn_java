# 学生管理系统 · 第九步：文件上传与操作日志

> 本篇完成两个进阶功能：① **文件上传**——学生照片上传落盘 + 公开访问，贯穿上传安全四件套（类型白名单 / 大小限制 / UUID 改名 / 路径穿越防护）；② **操作日志**——`@Aspect` 环绕通知无侵入拦截所有写接口，自动记录操作人 / 参数（脱敏）/ 结果 / 耗时。数据库以"全量 init.sql + 增量迁移脚本"方式演进。全部用例实测通过。

## 一、文件上传

### 请求形态

前端（你的老本行，一笔带过）：

```js
const fd = new FormData();
fd.append('file', fileInput.files[0]);
axios.post('/files/upload', fd, { headers: { Authorization: 'Bearer ' + token } });
// 注意：不要手动设置 Content-Type，浏览器要自己生成带 boundary 的 multipart/form-data
```

后端用 `MultipartFile` 接收——它是 Spring 对 multipart 请求中一个文件分区的抽象：文件内容 + 原始文件名 + Content-Type + 大小。默认配置下小文件在内存里，超过阈值落临时盘，对业务代码透明。

### yml 两道配置

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 5MB       # 单文件上限
      max-request-size: 6MB    # 单请求总量（多留 1MB 给表单其他字段）
```

超限会抛 `MaxUploadSizeExceededException`——**这个异常在进入 Controller 之前就抛了**，但 `@RestControllerAdvice` 照样接得住（它拦截的是整个请求处理链，不只是 Controller 方法体），全局处理器里转成 `400 文件大小超出限制（单个文件最大 5MB）`。

### 安全四件套（FileService 的核心）

**① 类型白名单——认 Content-Type，不认扩展名。** 扩展名 `evil.jpg` 改个名就骗过去了；浏览器会按文件头探测真实 MIME。白名单放在 yml（`storage.allowed-types`），经 `@ConfigurationProperties` 绑定成配置对象——比一堆 `@Value` 更集中、IDE 还能补全配置键。

**② 大小限制**——yml 兜底，不在业务代码里手写判断。

**③ UUID 改名——原始文件名一律丢弃。** 原始名可能携带 `../`、空格、中文、与存量文件重名，每一个都是事故源。落盘名 = `UUID（去横线）+ 原扩展名`，如 `d75d8875298f404baaf5b4903481de09.png`，原始名只存进返回值供前端展示。

**④ 路径穿越防护——读取接口的双闸门：**

```java
// 闸门一：文件名格式白名单，只认"32位十六进制名.图片扩展名"，../ 之类的直接拒收
private static final Pattern STORED_NAME_PATTERN = Pattern.compile("[a-f0-9]{32}\\.(jpg|jpeg|png|gif|webp)");

// 闸门二：normalize 之后复检仍在存储根目录内
Path target = storageRoot.resolve(filename).normalize();
if (!target.startsWith(storageRoot) || !Files.exists(target)) return null;
```

实测还发现了**第三道天然防线**：请求 `/files/view/..%2f..%2fapplication.yml` 时，Tomcat 默认拒绝路径中的编码斜杠 `%2F`，直接返回 400，请求根本没进应用。防御讲究纵深——每一层都不指望自己是最后一层。

### 两个设计决策

**库存路径，不存文件本身。** `student.photo` 存 `/files/view/xxx.png` 这样的路径字符串，文件躺在磁盘 `uploads/` 目录。不把文件塞进数据库 BLOB：备份膨胀、查询拖累、CDN 无法接管，全是坑。生产环境这一步会换成对象存储（OSS/S3），本项目的磁盘方案是它的简化同构版。

**读取接口公开，上传接口要登录。** 头像要能直接放进 `<img src>` 加载，而 img 标签发不出 `Authorization` 头——所以 `GET /files/view/**` 进了拦截器白名单，`POST /files/upload` 照常鉴权。生产环境的更优解是私有存储 + 临时签名 URL，这里先取简单方案，账记在文档里。

## 二、操作日志：AOP 的第一次实战

### 为什么必须用 AOP

反例先摆出来：如果不用 AOP，每个 Controller 方法都得长成这样——

```java
long start = System.currentTimeMillis();
try {
    // 真正的业务一行
    opLogMapper.insert(拼半天的日志对象);
} catch ...
```

十几个接口 × 十来行日志样板 = 业务代码被日志淹没，还必然漏写、写歪。**日志是"横切关注点"**：它不属于任何单个业务，却横穿所有业务。AOP 的价值就是把它抽出来，集中一处，声明式挂载：

```java
@OperationLog(module = "student", action = "CREATE")   // 业务方法只多一行注解
@PostMapping
public Result<Long> add(...) { ... }
```

### 术语对照表

| AOP 术语 | 本项目对应物 |
|---|---|
| 切面 Aspect | `OperationLogAspect` 类（`@Aspect + @Component`） |
| 切点 Pointcut | `@annotation(operationLog)`——"所有标了 @OperationLog 的方法" |
| 通知 Advice | `@Around` 环绕通知：能决定目标方法执不执行、拿到入参和返回值 |
| 连接点 JoinPoint | 每一次被拦截的真实方法调用 |
| 织入 Weaving | Spring 启动时为 Controller 生成代理对象，把切面逻辑编进去 |

### 环绕通知的执行模型

```java
@Around(value = "@annotation(operationLog)", argNames = "pjp,operationLog")
public Object around(ProceedingJoinPoint pjp, OperationLog operationLog) throws Throwable {
    // 前置：记操作人、请求信息、参数（脱敏）
    try {
        result = pjp.proceed();      // ← 放行，执行原方法。不调它，原方法就不执行
        return result;
    } catch (Throwable e) {
        // 记错误码：BusinessException 记业务码，其余记 500
        throw e;                     // ← 原样抛出，切面绝不能吞异常
    } finally {
        // 收尾：记耗时、写库。写库失败只记 error 日志，绝不影响业务返回
    }
}
```

三根红线都在注释里：**`pjp.proceed()` 必须调、异常必须 rethrow、日志写失败必须吞**。

### 切面里的两个"隔空取物"

切面不在 Controller 的方法签名里，拿不到请求对象和登录用户，靠两个上下文工具：

```java
// 当前请求：Spring 把请求绑在线程上，随时可取
ServletRequestAttributes attrs = (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
HttpServletRequest request = attrs.getRequest();   // -> method / URI / IP（先读 X-Forwarded-For）

// 当前用户：第七步拦截器存的 ThreadLocal，直接取
UserInfo user = UserContext.get();
```

**登录接口是个特例**：它在白名单里没走拦截器，`UserContext` 是空的，而且失败的登录（密码错）根本没有"登录用户"。处理：`finally` 里发现 username 为空时，从已记录的参数 JSON 里兜底提取 `username` 字段——实测日志里失败的登录照样记下了是谁试的：

```
id=2 | t_wang | auth | LOGIN | 1003 | 60ms | [{"username":"t_wang","password":"***"}]
```

### 参数序列化的三个坑位

`buildParams()` 里全踩了一遍并解决：

1. **`MultipartFile` 不能 JSON 序列化**（二进制流）→ 替换成占位符 `"[file: test.png, 70 bytes]"`；`HttpServletRequest` 同理；
2. **密码必须脱敏** → 正则把 `"password":"..."` 换成 `"password":"***"`（上面 id=2 那行就是效果）；
3. **长度必须截断**（1000 字符）→ 防有人传巨型 JSON 撑爆日志列。

### 日志表为什么没有 update_time 和 deleted

`op_log` 是**只追加**的审计数据：日志的意义在于"当时发生了什么"，可修改、可删除的日志没有审计价值。正好 MyBatis-Plus 的全局逻辑删除只对含 `deleted` 字段的实体生效，这张表天然不受影响——设计即规避。查询接口 `GET /logs` 挂 `@RequireRole("ADMIN")`，审计数据只对管理员开放（实测教师访问 → 403）。

## 五、高频坑位

1. **curl 上传被白名单拒**：`-F "file=@a.png"` 默认带 `application/octet-stream`，要 `-F "file=@a.png;type=image/png"` 显式指定；浏览器表单会自动探测，前端没这个问题；
2. **`@GetMapping("/view/{filename}")` 丢扩展名**：Spring 旧式路径匹配会截掉最后一个点后的内容，必须写 `{filename:.+}`；
3. **切面吞异常**：`catch` 里记完日志忘记 `throw e`，所有业务异常对前端变成 200 静默成功——灾难级 bug，`around` 方法的 catch 块要把 rethrow 当肌肉记忆；
4. **序列化请求对象**：`MultipartFile`、`HttpServletRequest` 直接 JSON 化会抛异常甚至拖垮响应，必须先替换成占位符；
5. **日志与业务同事务**：本项目没开事务问题不大，但一旦给 Service 加 `@Transactional`，日志插入默认并入同事务——业务回滚会把日志也回滚掉（失败操作恰恰最需要留痕）。届时日志写入要用 `Propagation.REQUIRES_NEW` 或异步化（`@Async` 另起线程，顺带解决日志拖慢接口的问题）；
6. **文件名信任**：任何用原始文件名拼路径的代码都是路径穿越漏洞，存盘名必须程序生成。
